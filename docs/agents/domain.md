# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.
This repository uses a single-context layout.

If a document is absent, proceed silently. Domain modeling creates
documentation when terminology or decisions are actually resolved.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
Treat missing concepts as possible domain-modeling gaps rather than
silently inventing synonyms.

## Decisions

Surface conflicts with existing ADRs explicitly, including the reason
for proposing a different decision.
