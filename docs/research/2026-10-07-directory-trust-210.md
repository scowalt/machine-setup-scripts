# #210: BB preparation directory trust

Scope: [#210](https://github.com/scowalt/machine-setup-scripts/issues/210), under [#208](https://github.com/scowalt/machine-setup-scripts/issues/208). Only the five identical `BEGIN_BB_MACHINE_PREPARATION` blocks, their version banners and preparation/service-reference fixtures change. Native server lifecycle, plugin refresh, desktop and their policy decisions belong to other slices.

Ordinary real directories owned by the configured non-root account now accept group write on Linux and Darwin without permission normalization or privacy proofs. This includes HOME/authorized ancestors, the separate preparation prefix and read-only service-reference ancestors. Existing group access can permit child replacement by another principal; this deliberately accepts that risk, not a claim of group isolation. No new locations, enrollment authority or readiness claims are introduced.

## Exact guidance changes for #217

Do not preserve the current CLAUDE.md BB-preparation statement that **Linux directory** group-write exceptions require a private ancestor or native exclusive-primary-group/ACL proof. Replace that policy with:

> Ordinary eligible account-owned real directories, including preparation prefixes and read-only service-reference ancestors, accept group write on Linux and macOS without directory privacy proofs or permission repair. Root/system boundaries, world write, foreign ownership and unexpected links remain blocked. Preserve the Linux-only private-ancestor/exclusive-primary-group/ACL exception for group-writable regular read-only service files; this exception and its NSS/initgroups/process evidence are not directory prerequisites. Preserve parent-first traversal, bounded diagnostics and stable service-reference snapshots, including accepted-mode changes.

Keep ADR 0003's separate-copy/manual-enrollment decision and its evidence unchanged; clarify the revised ordinary-directory prerequisite in #217's cross-component decision. Keep native server/override authority and the BB temporary-work private target outside this slice. Replace no incident history, README prose or broader guidance here. Residual tampering by service accounts with existing directory access must remain explicit.
