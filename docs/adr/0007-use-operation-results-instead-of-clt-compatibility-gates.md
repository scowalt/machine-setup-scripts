# Use operation results instead of CLT compatibility gates

The October 3 Mac setup log skipped Homebrew and downstream work because stale standalone CLT failed SDK diagnostics despite selected full Xcode; the owner subsequently reported that manual `brew upgrade` succeeded (not independently reproduced). Superseding the [September 28 policy](../brainstorms/2026-09-28-macos-clt-repair-requirements.md), ordinary macOS setup now attempts installations/upgrades without predictive compiler-readiness gates or automatic repair of existing CLT, including OpenCode's native Homebrew migration. Actual command failures and unverified required results remain failures, while first-time bootstrap, toolchain-selection preservation, ownership, credential and transaction safeguards remain intact.

Successful package maintenance does not establish readiness for future source builds or native addons; those operations may fail and require manual toolchain maintenance. The [extracted caller/bootstrap fixtures](../../tests/test_macos_clt.py) and [Homebrew-result fixtures](../../tests/test_homebrew_results.py) distinguish warning-only success from actual failures without running live setup.
