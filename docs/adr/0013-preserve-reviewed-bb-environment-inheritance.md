# Preserve reviewed BB account-environment inheritance during maintenance

The owner chose ordinary Ubuntu bb server maintenance over the retirement-first credential migration in [ADR 0011](0011-scope-bb-server-customizations.md), explicitly accepting continued access to the whole referenced account environment, including unrelated credentials ([authoritative #221](https://github.com/scowalt/machine-setup-scripts/issues/221)). Supersede that refusal only for the recognized existing app references below; setup retains maintenance responsibility. This is preserved systemd inheritance, not credential isolation, a data-only import into BB settings or a new configuration-precedence layer.

Accept at most one existing `env.conf` or `20-env-local.conf` whose exact bytes are `[Service]\nEnvironmentFile=%h/.env.local\n`, alone or with the reviewed private `10-tmpdir.conf`. The account-owned, single-linked, non-executable, reference-only regular file may retain group write, including the captured `0664`, without chmod/chown or group-membership proofs. This narrow non-secret file exception does not extend to other service/configuration/unit/guard files or credentials; [ADR 0012](0012-accept-account-owned-ordinary-directories.md) independently governs ordinary directories, including the captured `0775` container. Preserve private TMPDIR target/override and direct credential safeguards. Source safety checks use bounded metadata, not environment values; setup neither reads those values for this preflight nor creates, imports, rewrites or retires the source/reference.

Keep the finite filename/content contract, parent-first no-follow traversal, exact setup fragment and complete ordered local/loaded selection, and identity/UID/GID/mode/content revalidation before mutation. Unknown, hidden, duplicate, conflicting, alternate/optional references and ingress customizations remain blockers, as do linked, multiply linked, wrong-type, foreign-owned, world-writable or special/executable reference artifacts. Absent/verified-empty and TMPDIR-only cases remain supported without seeding inheritance. Existing account/platform/opt-in, package identity, npm policy, native locks and managed listener/endpoint conflict checks remain intact.

The setup run is the interruption window: stop own ingress before app, update while stopped and restart automatically without a migration inventory, paid provider probe or manual startup checkpoint. Success requires managed app/host readiness, active app and ingress, and verified saved private endpoint; a start request is insufficient. Preserve accepted bytes/modes, native credentials/settings, temporary work and unrelated state. Keep existing best-effort service restoration, not new rollback machinery: restored availability never erases a required update/readiness failure or proves package/configuration/session rollback. Failures still defer default plugin refresh, allow independent work and finish logging nonzero; successful BB maintenance permits refresh through its existing gates without clearing unrelated failures.

The [Beelink retirement procedure](../plans/2026-10-06-bb-environment-override-migration.md) and [Devinabox packet](../plans/2026-10-07-devinabox-bb-environment-migration.md) remain historical, not prerequisites for this path. #204/#207 remain open, not completed migrations. Repository implementation and contained evidence authorize no live setup or service action; native rollout remains separately authorized. Readiness alone proves neither browser/WebSocket continuity, provider/tool usability nor reboot continuity.
