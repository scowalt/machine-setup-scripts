# Accept account-owned Pi trust-file group write

The October 15 Beelink setup run failed on a valid, account-owned `~/.pi/agent/trust.json` with mode `0664`; Pi's native trust writer creates that mode under umask `0002`. Scott chose to accept existing group write for this file instead of recurring permission repair or a service-wide umask change. Setup's Unix trust-file validator therefore rejects world write, not group write; group members with existing access may alter project trust and authorize project resources, an owner-accepted risk rather than isolation.

This narrowly extends [ADR 0012's preserved regular-file policy](0012-accept-account-owned-ordinary-directories.md) for the active profile's `trust.json` only. Preserve account ownership, regular/single-link/size and JSON validation, private profile boundaries, native locks, stable identity/UID/GID/mode/content snapshots and Windows ACL policy. Do not relax credential or adapter CLI file checks, broaden trusted roots, or approve MCP definitions; [ADR 0015's two-gate contract](0015-trust-pi-workspace-roots-without-approving-mcp-definitions.md) is unchanged. No permission repair or group-membership proof is required. [Offline regressions](../../tests/test_bb_pi_trust.py) cover the captured native writer under umask `0002`, all six embedded wrappers, accepted-mode races and retained refusals; they are not live rollout evidence.
