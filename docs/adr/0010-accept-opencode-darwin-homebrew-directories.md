# Accept account-owned macOS Homebrew directories for OpenCode

Supersedes the [exact-bin exception](0008-accept-opencode-darwin-homebrew-bin-group-write.md). The later owner-supplied Mac capture reproduced `brew-path` at group-writable `/opt/homebrew/Cellar` after passing `bin`; the same policy also rejects the captured `var` and `var/homebrew` modes. Scott chose a setup-script change rather than machine permission changes. To avoid moving the refusal from one directory to the next, OpenCode accepts existing group write on real directories owned by the non-root invoking account within either recognized macOS Homebrew prefix (`/opt/homebrew` or `/usr/local`), including the prefix itself. This does not claim every machine has those modes.

This is a directory-only exception reached through the existing recognized Homebrew command/Cellar/receipt/pin paths, not trust for arbitrary commands under those prefixes. Regular files remain non-group-writable; system parents, linked ancestors, foreign owners, root-owned group write and world write remain rejected. Preserve parent-first traversal, mode/group/identity snapshots, pins, official-byte verification and [command-only migration/rollback](0004-keep-opencode-migration-command-only.md). Add no chmod, group-privacy probes or override. Linux keeps its [separate existing policy](0005-accept-opencode-linux-homebrew-group-write.md); Windows, standalone/package commands, BB and credentials are unchanged.

Other principals able to write these directories can replace children; official-byte checks and revalidation do not eliminate every concurrent-write race. That residual risk is accepted without claiming exclusive groups or ACL privacy. The [captured-state replay](../../tests/test_opencode_macos_preflight.py) now reaches the uncaptured receipt boundary, while [inert migration fixtures](../../tests/opencode-cli.test.cjs) cover both prefixes, group-writable ancestors, absent/present pin directories, rejection boundaries and rollback. The capture was taken after the failed run, not atomically with it; receipt contents and native Mac recovery remain unverified.
