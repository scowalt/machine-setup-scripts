# Preserve selected Visual Explainer optional dependencies around native Pi updates

Visual Explainer documents installing its optional `playwright-core` beside the plugin, but setup's root-only generated-artifact allowance rejected that layout. Pi 1.4.0 also cleans ignored Git-package artifacts on revision changes, then installs with `--omit=dev --legacy-peer-deps`; merely allowing the directory would silently remove the optional capability. Preserve an existing verified copy around native installation and package refresh rather than fetching a replacement, changing its selected version, relaxing npm policy, or replacing Pi's updater.

Only the documented `plugins/visual-explainer/node_modules` layout qualifies, with the named package, bounded owned regular files, validated lock metadata when present, and npm's exact internal executable link. Other packages, unknown checkout artifacts and unsafe links still block maintenance. Move the original directory into a new private `.setup-visual-explainer-dependencies` reservation in the active global Pi profile, outside native cleanup, and restore its original files and identities after the child finishes, including on failure. This does not install Playwright when absent or prove its dependency bytes match a registry artifact.

If interrupted or unable to restore safely, retain recovery data and fail closed; a pre-existing reservation requires operator reconciliation rather than automatic deletion or overwrite. Setup may temporarily interrupt access to this optional dependency, consistent with ordinary setup's disruptive behavior. The contained regressions in `tests/test_visual_explainer_dependencies.py` exercise real Git cleanup with inert Pi commands; native-platform usability and live rollout remain separate evidence.
