# Leave bb desktop owner-managed

The owner maintains a custom bb desktop fork and chose to stop setup's desktop installation/update management on every headed machine after the [Neo ambiguity failure](../research/2026-10-16-neo-bb-setup-failures.md). All six entry points now leave desktop installations unmanaged, with no new opt-out required; headless runs remain non-installing. Preserve existing official/custom/nightly copies, links, menu entries and recovery state without inspection, replacement, permission repair or cleanup. The owner, rather than setup, owns desktop installation, upgrades and compatibility.

This supersedes the desktop installer and its [native Applications transaction exception](0006-accept-native-macos-applications-for-bb-desktop.md). It preserves remote main's separate exact-`HEADLESS=1` gates for BB machine preparation and Ubuntu's opted-in independent server; enrolled roles and verified local-server plugin refresh remain independent. Plugin discovery retains its existing safeguards and can still fail independently; desktop non-management grants no new trust or permission exceptions. The [contained non-management contract](../../tests/bb-desktop-contract.sh) checks absent apps and preserved forks/duplicates/links plus independent failure/logging behavior; no live setup or app execution validates this decision.
