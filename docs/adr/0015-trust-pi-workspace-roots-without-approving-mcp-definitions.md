# Trust Pi workspace roots without approving MCP definitions

The owner wants fresh BB threads to inherit Pi project trust rather than require per-worktree entries. Ordinary setup merges the canonical BB plugin worktree root, BB thread-storage root and `~/Code` into the active global Pi profile's trust store, deriving BB paths from `BB_DATA_DIR` (default `~/.bb`). This deliberately allows project resources, including extensions, under these roots; it is not isolation. Preserve existing decisions, including ancestor/root denials and more-specific descendant denials, inactive profiles and legacy-worktree entries. Do not trust all of HOME or BB data, enumerate thread directories, or manage legacy services.

Folder trust does not authorize arbitrary MCP definitions. Preserve the adapter's existing approval store byte-for-byte; native repository-scoped approvals provide worktree inheritance only for identical reviewed definitions. Do not seed approvals from discovered files, set global `projectServers: "allow"`, or broaden `defaultProjectTrust`. Setup merges metadata after private Pi profile preparation and before package operations, without starting MCP servers. The explicit health diagnostic runs `doctor --json` and treats `blocked` results as failures even when doctor exits zero. [Offline admission fixtures](../../tests/fixtures/bb-pi-trust/README.md) pin this two-gate contract; native platform and live server readiness remain separate evidence. [ADR 0016](0016-accept-account-owned-pi-trust-file-group-write.md) permits account-owned Unix trust-file group write without changing these trust or MCP approval decisions.
