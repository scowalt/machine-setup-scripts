# Accept account-owned ordinary directories across setup

Repeated group-write refusals moved from one tool or ancestor to the next, culminating in nine Impeccable directory gates ([#208](https://github.com/scowalt/machine-setup-scripts/issues/208)). Within each operation's existing authorized locations, accept real ordinary directories owned by the configured non-root account with their existing group access, without chmod, exclusive-group/private-ancestor proofs, NSS/initgroups/ACL privacy scans or a quiet process table. Other principals with existing access—including compromised service accounts—can replace children; ownership, official bytes and snapshots do not eliminate every concurrent-write attack. Scott accepts that residual risk instead of recurring permission repair; this grants no new filesystem access or management authority.

Preserve world-write/foreign-owner rejection, root/system and reviewed link boundaries, regular-file rules, native Windows ACLs, explicit Pi profile/direct credential privacy, private staging/locks/recovery and BB's private TMPDIR target. Ordinary configuration, service/drop-in and data containers are not private merely because they contain protected files. Retain identity/UID/GID/mode revalidation even between independently accepted states and preserve actual failures through final logging.

This supersedes only the component/prefix/absence-only **directory limits** of [0005](0005-accept-opencode-linux-homebrew-group-write.md), [0008](0008-accept-opencode-darwin-homebrew-bin-group-write.md), [0009](0009-limit-bb-group-write-exception-to-negative-discovery.md) and [0010](0010-accept-opencode-darwin-homebrew-directories.md). OpenCode's Linux Homebrew regular-file allowance and BB preparation's Linux regular-service-file privacy proof remain scoped exceptions, not ordinary-directory prerequisites. [Command-only migration](0004-keep-opencode-migration-command-only.md), [native Applications ownership](0006-accept-native-macos-applications-for-bb-desktop.md), [preparation/enrollment separation](0003-separate-bb-preparation-from-enrollment.md) and [supported customization authority](0011-scope-bb-server-customizations.md) remain intact. Directory acceptance neither imports nor retires BB environment overrides. [ADR 0013](0013-preserve-reviewed-bb-environment-inheritance.md) separately permits the recognized existing app reference and its narrow non-secret regular-file exception; it does not change this directory policy. #204/#207 remain historical open migrations, not prerequisites for that preserved-reference path; live authorization remains separate.

The [integrated gate inventory and contained evidence](../research/2026-10-07-directory-trust-integration.md) distinguish changed, preserved and already-compatible behavior. No live setup, permission repair or rollout validates this decision; historical capture and containment-incident uncertainty remain unchanged.
