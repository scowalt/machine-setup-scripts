# Accept native macOS Applications for account-owned bb desktop

Historical: [ADR 0017](0017-leave-bb-desktop-owner-managed.md) retires setup's desktop installer in favor of the owner's custom fork. The captured evidence and former transaction policy below are retained; this is not a current plugin-discovery or directory-trust exception. Before retirement, eligible account-owned descendants and user destinations followed [ADR 0012](0012-accept-account-owned-ordinary-directories.md), without generalizing the privileged-parent exception.

The supplied `scott-macbook-m3` metadata for mac.sh 267 (`afe9fd9`) shows `/Applications` as root:admin 0775 and `bb.app` as account-owned 0755. Installer-seam fixtures reproduce both refusals: the generic group-write guard, then the account-owned-parent requirement even at 0755. Accept only native macOS `/Applications`, a real root-owned directory with native admin GID 80 and mode 0755 or 0775, for maintaining an already-present, account-owned, verified official bb desktop app. Keep fresh installs in `~/Applications`; permission repair, elevation and silent relocation/duplication are not alternatives.

This explicitly trusts native administrators who can replace directory entries without sudo. It is not an exclusive-group or ACL privacy proof, and point-in-time filesystem/signature checks cannot eliminate concurrent administrator replacement races. Revalidate ancestor identity, ownership, group and mode plus private account-owned lock/stage identities before promotion, rollback and cleanup; retain recovery state on uncertainty. Keep bundle ownership, official artifact/signature/notarization checks, running-app deferral and custom/nightly/newer-copy safeguards. The exception neither extends to descendants or other directories nor changes Linux (including the separate [OpenCode Homebrew decision](0005-accept-opencode-linux-homebrew-group-write.md)), Windows, WSL, BB server or credential policy. The former inert desktop fixtures modeled metadata and native checks; actual macOS ACL/signature/GUI behavior was not established by Linux fixtures. The current [desktop contract](../../tests/bb-desktop-contract.sh) instead verifies non-management.
