# Accept native macOS Applications for account-owned bb desktop

Current scope: the native root:admin `/Applications` exception below remains unchanged. Eligible account-owned descendants and user destinations now follow [ADR 0012](0012-accept-account-owned-ordinary-directories.md), without generalizing this privileged-parent exception.

The supplied `scott-macbook-m3` metadata for mac.sh 267 (`afe9fd9`) shows `/Applications` as root:admin 0775 and `bb.app` as account-owned 0755. Installer-seam fixtures reproduce both refusals: the generic group-write guard, then the account-owned-parent requirement even at 0755. Accept only native macOS `/Applications`, a real root-owned directory with native admin GID 80 and mode 0755 or 0775, for maintaining an already-present, account-owned, verified official bb desktop app. Keep fresh installs in `~/Applications`; permission repair, elevation and silent relocation/duplication are not alternatives.

This explicitly trusts native administrators who can replace directory entries without sudo. It is not an exclusive-group or ACL privacy proof, and point-in-time filesystem/signature checks cannot eliminate concurrent administrator replacement races. Revalidate ancestor identity, ownership, group and mode plus private account-owned lock/stage identities before promotion, rollback and cleanup; retain recovery state on uncertainty. Keep bundle ownership, official artifact/signature/notarization checks, running-app deferral and custom/nightly/newer-copy safeguards. The exception neither extends to descendants or other directories nor changes Linux (including the separate [OpenCode Homebrew decision](0005-accept-opencode-linux-homebrew-group-write.md)), Windows, WSL, BB server or credential policy. The [inert desktop fixtures](../../tests/test_bb_desktop.py) model metadata and native checks; actual macOS ACL/signature/GUI behavior remains rollout evidence, not established by Linux fixtures.
